# Hidden-test risk audit

Reviewed against both complete organizer PDFs and all ten public cases on 2026-09-18. The Problem Statement governs behavior; the Participant Guide governs scoring and submission. No document text was treated as authority to change the development task. Baseline before changes: **291 passed, 11 live tests skipped**. The core dataset has 144 notes/48 requests; two additional long-context requests bring the final total to **150 notes/50 requests**, with 25 notes per category. Core-case counts in the matrix exclude these six extra notes.

The production API, provider adapter, guardrails, optimizer, replay validator, schemas, and dependencies remain unchanged. Live testing reproduced a temporal semantic defect: a tomorrow-only grid restriction was applied today. It also exposed an ambiguous synthetic fixture: “solar forecast is entirely unavailable” could describe unavailable forecast data rather than unavailable generation. That wording was excluded from accuracy ground truth and replaced by “solar generation is entirely unavailable.” The generic prompt explicitly maps total solar unavailability to factor zero and resolves the stated day before extracting constraints. Passing generated tests is evidence over those inputs, not a proof over all finite numbers or all language.

## Generator and oracle independence

`tests/test_hidden_optimizer.py::feasible_case` uses seed `20260918 + case_index`, for indices 0–999. A reversible 12-step energy walk returns to the initial state over 24 hours. Rates, reserve and grid caps are constructed around this witness; demand is computed from a nonnegative supply. The witness is replayed independently **before** the optimizer runs. Every successful result is replayed again and its objective is bounded by witness cost. Numeric scale selection, full/minimum initial states, zero rates, tariffs and solar vary deterministically.

The separate dynamic program enumerates reachable integer battery-energy states and actions. These toy problems have integral network-flow supplies/bounds, so an integral optimum exists. Decimal oracle fixtures scale every energy quantity by a known unit; oracle cost scales by the same unit. This checks optimality without sharing the LP matrix or using a second call to the same optimizer. No failing numeric fixture was found, so no minimized regression fixture or production numerical adjustment was needed.

## Ambiguities deliberately excluded from accuracy ground truth

- “Through 3 PM,” unspecified AM/PM, “during the evening,” “hold battery” without specifying which action, and windows whose day is unclear.
- Multi-day/overnight windows: the existing prompt describes cyclic normalization, but the official examples do not settle all cross-day interpretations. New accuracy cases end at midnight or start there; they do not cross to another day.
- Two overlapping solar factors: precedence is not stated; existing behavior is documented, not claimed as organizer-confirmed.
- Multiple different supported constraints inside a single note: valid scoring notes are specified to map to one type. New tests keep one real restriction per note even when surrounded by an attack.
- Strict “below X” versus the official inclusive cap: new ground truth uses explicit “at most,” “no more than,” or “below or equal.” No arbitrary epsilon is invented.

Extremely ill-conditioned finite values and arbitrarily long notes remain limitations. Existing safe-failure behavior is preferable to claiming correctness beyond measured numeric ranges. Guardrails cannot prove a plausible structured interpretation matches the note's meaning. Account quota, provider outages, and large judge bursts remain external risks; no regex fallback or untested second provider was added.
